## 飞书配置答疑
- 用户问：完成第三步“创建飞书企业自建应用并开通权限”后，能否通过授权让它自动创建第四步到第七步（多维表格、三张表、字段、获取 app_token/table_id）。
- 答复要点：技术上可以部分/大部分自动化，思路是用 tenant_access_token 调飞书多维表格/字段相关 OpenAPI 创建 base、tables、fields 并保存 token/id；但首次 MVP 更稳妥的做法是手动创建 base，或者新增一个仅内部使用的 `setup-feishu` 脚本/API 自动建三张表和字段。自动化需要额外权限、空间归属和字段类型兼容处理，调试成本高于手动配置。

## 飞书同步状态 Bug 修复
- **问题**：结果页顶部总是显示"报告已生成，但后台同步失败"，即使飞书同步实际上最终成功。
- **根因**：`app/assessment/page.tsx` 在调用 `/api/leads` 前先写入 localStorage `{ success: false, error: "后台同步中" }`，而 3.6 秒后跳转到结果页时，`ResultClient.tsx` 只检查 `!syncStatus.success`，把"同步中"误判为"同步失败"。
- **修复**：
  1. `src/types/index.ts`：`FeishuSyncStatus` 增加 `status?: "pending" | "success" | "failed"` 字段
  2. `app/assessment/page.tsx`：初始状态设为 `status: "pending"`；API 返回后设为 `"success"` 或 `"failed"`；catch 块设为 `"failed"`
  3. `components/ResultClient.tsx`：区分三种状态分别显示不同文案（蓝色提示/红色错误/兼容旧数据的红色错误）；新增轮询 useEffect，每 1.5 秒检查 localStorage，当 pending 变为 success/failed 时自动更新 UI
- **验证**：`npm run lint` 通过、`npm run build` 通过、已推送 GitHub（commit f6a45ff）
